# Darkflix

Darkflix (formerly Dagflix and Flipflix) is a native Android TV / Fire TV discovery app with remote-friendly browsing, title details, trailers, Library, watch history, and third-party playback providers.

This is an experimental project. Favor small, fast iterations and checks scoped to the behavior being changed, on the actual TV unless requested otherwise. The owner permits resetting/reinstalling this app and discarding its test data when useful; do not add data-preservation or migration work by default. This does not authorize deleting unrelated projects or device data.

Download the latest APK: https://tinyurl.com/24qywecz

The GitHub repository and releases are public. The stable short link targets the latest `app-release.apk`.

## Rift native audio fix (v0.1.30, historical)

- Root cause: Rift's HLS loader preloads the master playlist without making a Resource Timing entry. The previous discovery heuristic selected a later video-only child playlist, losing the separate audio rendition. The master observed on the TV contains three video levels and AAC audio; this was a source-selection error, not a VLC codec or mute-setting problem.
- Discovery now observes HLS.js's public [media attachment](https://hlsjs.video-dev.org/api-docs/hls.js.hls.attachmedia), associates each instance with its exact video element, and hands VLC that instance's [current input URL](https://hlsjs.video-dev.org/api-docs/hls.js.hls.url). It preserves the original method's arguments and result, rejects detached owners, and restores the method on handoff. If a known HLS player has no usable input URL, discovery does not substitute a guessed video child.
- The observer runs on library/media events, not a polling loop. No extra manifest requests, guessed provider endpoints, payload decryption, persisted stream tokens, or player-engine changes were added. Rift remains native-only; Bolt's existing web fallback remains.
- Both the original live audio test and a deterministic real-WebView test failed before this fix and passed afterward on the actual onn TV box over wireless ADB. The WebView regression uses a closure-private HLS instance, an unrelated second player, a preloaded master absent from Resource Timing, and a visible video-only child. The live Rift/Sintel test requires a selected native audio track, decoded-audio and played-audio-buffer counters, mute/unmute, seek and pause. This verifies delivery to Android's audio output, not physical speaker loudness or every provider title.

Five focused TV checks passed across two runs: live Rift native audio/controls, the master-selection regression, scoped one-shot discovery/stale-session rejection, cross-provider native resume, and Bolt web recovery/audio after a native failure. Release build/lint (zero errors, 72 warnings), signing and 16 KB ZIP alignment passed. No emulator or full-suite run was used.

## Native-only Rift, Bolt web fallback (v0.1.29, historical)

- Rift now uses a hidden, non-focusable, muted WebView only to discover an ordinary direct stream. VLC is its only playback backend. Rift's old provider controller and web-player fallback are not instantiated. Fast and sports retain their existing routes.
- Bolt keeps its visible web player when a usable direct URL cannot be discovered. If a discovered stream plays in VLC, native playback takes over. If that native attempt fails, Bolt returns once to web playback at the shared resume point, without a discovery/retry loop. Explicit Retry or selecting a source permits a fresh attempt.
- The entire resolver WebView is muted with AndroidX's [WebView audio API](https://developer.android.com/reference/androidx/webkit/WebViewCompat#setAudioMuted(android.webkit.WebView,boolean)), including nested frames. It cannot open a fullscreen/custom view or take remote focus. Its clock cannot update watch history or replace a saved resume point.
- Rift discovery has a 45-second limit. Failure or unsupported WebView capabilities leaves Source, Retry and Back available, with no web fallback. Retry creates a new discovery lease; late results/timeouts from old leases are ignored. A successful handoff stops/blanks the resolver before VLC starts and restores the shared movie/episode checkpoint.
- Rift resolution requires document-start scripts, origin-scoped messages, and WebView audio muting. Older Fire TV WebViews lacking these features cannot resolve Rift natively; Bolt/Fast retain web playback. A title may also fail if its provider does not expose a usable direct URL. No DRM, authentication, or provider protection is bypassed, and signed URLs are not persisted.
- This release changed playback policy, not stream selection. Its Rift video-only HLS input issue was subsequently fixed in v0.1.30 above. Only tracks available in the direct stream can appear in native controls.

Live verification on the actual onn TV: Sintel on Rift reached VLC with 885-second metadata and acknowledged a seek to one minute and pause. Bolt did not resolve in the observed attempt; a subsequent switch to Rift must not be counted as Bolt success. Live audio was not verified in these resolver checks. Keep tests narrow; no emulator or full-suite run is needed for this policy change.

Five focused regression checks passed across targeted TV runs: Rift control ownership/fullscreen rejection; timeout/retry/source/episode/Back navigation; scoped one-shot discovery; native cross-provider resume; and Bolt recovery after an actual VLC failure, including restored WebView audio and the shared checkpoint. The final fallback test passed in 6.9 seconds. Embedded documents can report `about:blank` from `getUrl()` when their history URL is null, so audio restoration uses their completed-page callback URL. Release build/lint (zero errors, 72 warnings), signing and 16 KB ZIP alignment passed.

## Native-first playback (v0.1.27, historical)

- Movie/episode playback observes the selected provider's normal video loading. If that exact provider frame exposes an ordinary HTTPS video or HLS/DASH manifest and full-length metadata, Darkflix stops the web player and hands playback to native Media3/ExoPlayer. It does not decrypt provider payloads, guess protected endpoints, bypass DRM, or persist stream tokens.
- ExoPlayer tries available platform decoders first. Unsupported audio, player errors, or a bounded preparation timeout switch once to the bundled LibVLC 3.7.7 native engine, which supplies broader audio/video decoding. No external VLC installation is required. LibVLC is the extra codec path; this release does **not** build or bundle Media3's separate FFmpeg audio extension.
- Both native engines use the existing Darkflix remote controls, accelerating seek, pause/play, mute, Fit/Fill, subtitle and source-provided audio-track choices. ExoPlayer exposes available video-quality tracks; VLC uses automatic adaptive quality. Provider-only server lists, styling, or separate language-version features may be unavailable after native handoff.
- History is still keyed by movie/episode, not provider or engine. Handoff captures progress before releasing the outgoing backend. Exo-to-VLC fallback preserves the current position, pause, mute and Fit/Fill. Back releases both engines; leaving the Activity pauses native playback.
- The controls identify the active engine: `Bolt / ExoPlayer`, `Rift / VLC`, or `Fast / Web`, for example. If no usable URL is exposed, the existing web integration remains and is explicitly labeled Web. Sports stays on its existing route. Once native playback starts, a failure does not silently return to an embed or loop indefinitely: Source, Retry and Back remain available.
- Discovery is event-driven, source-origin/session scoped, and cancelled on source change/exit. Short clips, DRM signals, stale documents, ambiguous cross-host manifests, and materially mismatched native durations are rejected. It depends on WebView document-start/message support; older WebViews retain the Web route. This cannot guarantee a direct stream for every provider or title.
- Compile SDK 36 and AGP 8.10.1 support the current stable LibVLC dependency. Minimum Android remains 5.1/API 22 and target API remains 33. ARMv7, ARM64, x86 and x86_64 are packaged; the universal APK is larger because it now includes actual native codec libraries. All SDK packages remain in `/home/okonu/Android/Sdk`.
- Software notices and LGPL/Apache license texts are available under Profile > Media credits > Software licenses, with upstream source/build links.

## What works

- A cinematic native discovery Home with a persistent profile/search/browse/library rail, shared artwork hero, and horizontal rows. The hero occupies the upper 55% and keeps title information visible while rows scroll beneath it
- Featured picks (daily trends), Trending, Movies, TV Shows, Crime TV, Comedy TV, a mixed-size Spotlight (weekly movie trends), New releases, Comedy movies, Anime, and Live Sports. Every production row is populated by its catalog endpoint; there are no bundled recommendations. Rows fetch more pages near the end and keep later selected cards near the left content edge. Clicking Spotlight opens the matching weekly movie collection.
- Home cards use 16:9 artwork with labels below, about four complete cards plus a partial next card on a 1080p TV. Spotlight combines a wide promotion and taller posters. Collection and search grids use the same artwork-first cards and labels beneath, five across. White rounded focus borders have room on every edge
- Horizontal page changes, vertical page/row navigation, and season choices glide into place with a 220-320ms decelerating animation at the normal system animation scale. Focus changes immediately; repeated presses retarget from the current position instead of queuing animations. Home headings stay visible with their row, final cards remain whole, and motions are cancelled when leaving a screen or starting a touch gesture
- Selectable row headings open full-page collection grids with a Load more control. The shared rail appears on Home, Library, collections, search, and details. Browse offers direct Home, Movies, TV Shows, Trending, Anime, Live Sports, and Library destinations. Movies/TV Shows headings also show a Browse & filter hint. Search is available from the rail and existing collection headers
- Movies and TV Shows have native remote-friendly Genre, Year, Minimum rating, Country, and Sort by menus plus Reset filters. Combine filters across the full catalog, with Most popular, Highest rated, Newest first, or Oldest first sorting. Movie year means original release year; TV year means first aired. Each section remembers its own choices across details, playback, and app restarts; Home rows stay unfiltered

### Sports compatibility notes

The observed `Remove sandbox attributes on the iframe tag` warning comes from a hidden `object#sandDetect` PDF failing to load, not an iframe added by Flipflix. `sports-compat.js` only handles that exact PDF error on a top-level HTTPS `embed.st/embed/` page; real iframes, other documents, and unrelated errors are left alone. Current WebViews install the handler at document start. Older WebViews insert it into this provider's initial HTML before its scripts, preserving response security headers and leaving media traffic untouched.

This fixes the false warning, not all provider/browser incompatibilities. The API 30 TV emulator's WebView 90 also fails on the provider's newer WebAssembly code, so removing the warning there does not prove live-video playback. Live playback still depends on a sufficiently current WebView, a working provider stream, and supported codecs. No WebView engine or device-wide settings are bundled or changed by this update.

`sports-start.js` is limited to the same top-level sports documents. It targets JW Player's documented `jwplayer('player').play()` API, with a fallback to the observed JW display Play button inside `#player`. It never taps arbitrary screen coordinates or advertisement links. A rejected autoplay can be retried from the native Play control; provider or network failures still require Retry or another stream. The early-injection path works on old WebViews as well as those supporting document-start scripts.

## TV scrolling

The scrolling behavior follows the focus-aware alignment and bounded-pending-movement principles used by [Android Leanback](https://developer.android.com/reference/androidx/leanback/widget/BaseGridView) and [DpadRecyclerView](https://rubensousa.github.io/DpadRecyclerView/recipes/scrolling/). Discovery uses a left-anchored carousel with one shared hero; existing collection grids retain their paging behavior without migrating to either library.

`TvScrollMotion` animates only scroll offsets using Android's frame-synced `ValueAnimator`, which honors the system animation scale. There are no timers running while idle and no per-frame layout or network operations. `TvHorizontalScrollView` and `TvScrollView` suppress the framework's immediate focus-reveal jump, retain focus bookkeeping, and animate a single current destination. The vertical scroller groups Home headings with their carousel. Initial layout and explicitly immediate visibility requests remain immediate; regular remote navigation animates. Appending catalog pages preserves the current focus and does not restart an unchanged destination.

## Playback regression tests

`RiftPlaybackTest` exercises the production wrapper in a real WebView against a deterministic cross-origin provider fixture: command units/IDs, changing track lists, subtitle appearance/sync, errors, exclusive control ownership through pause/reload/handoff, retained video/captions/errors, origin/frame/episode rejection, and closed-session cleanup. `SeekAcceleratorTest` uses a deterministic clock for acceleration tiers, stale position accumulation, throttling, reset, and bounds. Playback controls also test held remote OK, key-up consumption, and audio-menu navigation. These tests verify our integration contract, not availability of every live provider stream. The bridge subscribes once to [Rift's state API](https://vidrift.net/docs/) per iframe load, with no background polling or DOM scanning. Only the app-owned top-level document reports playback state to the native listener; it validates the provider frame, exact origin, title/episode, and session. A separate presentation-only bridge in the exact Rift provider origin receives a session-validated native/provider visibility flag. It cannot issue player commands or call arbitrary Android APIs, and is removed with the player session.

The optional `RiftPlaybackTest#liveRiftProbe` accepts `-Pandroid.testInstrumentationRunnerArguments.liveRift=<TMDB movie ID>`. On 2026-10-24, the actual onn 4K TV box (Android 14, WebView 155) played Sintel (TMDB 45745) through the real Rift iframe. It reported an advancing position, playing state, 885-second duration, and audio/server/source/settings lists. This verifies live playback and the message handshake, not every title, dubbing track, or casting device. Those still depend on the provider and device. Do not work around provider checks.

`DiscoveryCatalogTest` exercises the actual production Home builder, catalog-only recommendations, honest offline states, bounded refresh and stale-callback rejection, matching Spotlight routing, release-date bounds, and removal of only the two legacy demo bookmarks while retaining real bookmarks and history. `DiscoveryTest` verifies selection/hero consistency, per-row memory, rail/headings, scrolling, full focus outlines, mouse/touch, compact layouts, Library, real local video decoding, preview cancellation/fallback, lifecycle, and reduced motion. Those licensed playback fixtures are debug-only and do not ship to viewers.

`PlaybackControlsTest` runs on the connected Android TV device.
